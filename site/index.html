简介 · Introduction

把生产计划的复杂度
交给会推理的系统

排产表上每一次插单、每一台设备的意外停机、每一批物料的延迟到货，都会牵动后面几十道工序。这些连锁反应过去只能靠计划员在脑子里过一遍，Maestro 让它们在发生之前就被算清楚。

  • 智能排产

    从人工排班表，走向同时考虑交期、产能、工艺约束与优先级的自动排程。计划员从「一格一格填表」回到「审阅与决策」。

  • 动态调度

    急单插入、设备故障、物料未到——异常发生的那一刻就重排，并把「这一改会影响哪些订单、推迟多少」一起算给你看。

  • 齐套与异常预警

    提前识别缺料、瓶颈工序与交期风险，在停线之前把问题推到人面前，而不是等到早会上复盘昨天为什么没做出来。

  • 决策可解释

    每一次调整都留下依据与过程：为什么这样排、谁批准的、当时依据的是哪份数据。不是黑箱给结论，而是能被追问、能被复核。

文档 · Architecture

一个请求，是怎么走完全程的

Maestro 不是「把提示词丢给模型」那种做法。每个请求都会成为一次可持久化、可恢复、可审计的执行，并且在产生任何副作用之前，必须先经过同一道授权关卡。

  • 01

    一切皆 Run

    每个请求都会成为一次持久化的执行单元，带完整状态机与步骤轨迹。进程崩了可以从落盘状态继续，无法被证明安全的执行则拒绝恢复。执行路径只允许从快速循环升级为受控执行，绝不反向降级。

  • 02

    策略门是唯一授权路径

    所有副作用只有一条通路。确定性规则按固定优先级裁决：放行、要求审批、或直接拒绝。高危写操作要求两次人工确认，两次之间外部状态若发生变化，先前的确认即刻作废。

  • 03

    能力可插拔

    运行时本身不含任何业务逻辑。排产、齐套、派工这些能力，以受治理的 Skill、Tool 或 MCP 在运行时装载，纳入同一套风险等级与权限体系。装载方只能收窄权限，永远无法为自己提权。

  • 04

    人在环中

    需要人拍板的动作会生成审批记录并把执行挂起，而不是先做了再报备。审批按修订号进行，基于过期状态作出的批准自动失效——你批准的一定是你当时看到的那件事。

  • 05

    可信执行边界

    外部脚本的执行权限绑定其内容哈希，改动一个字节，原有信任立即失效并重新走审批。隔离环境只是收敛手段，不冒充安全边界——真正的闸门始终是那次人工批准。

  • 06

    降级仍可用

    未配置模型密钥时，运行时依然能创建、恢复、取消、审批和审计执行，只是模型给出的回答进入受限行为。治理能力不依赖外部服务可用性。
