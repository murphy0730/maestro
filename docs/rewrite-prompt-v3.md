# 任务：基于 v2 设计系统全面重写 Maestro 前端

> 用途：将本文从“## 1. 角色与目标”起完整交给 Codex、Claude Code 或其他代码 Agent 执行。
>
> 视觉依据：`docs/design/maestro-design-system-v2.html`（深空指挥舱 · 2026-07-23）

## 1. 角色与目标

你是一名资深前端架构师、产品设计工程师和端到端测试工程师。请在当前仓库中直接完成 Maestro 前端的全面重写，不要只输出建议、计划或静态原型。

以 `docs/design/maestro-design-system-v2.html` 为唯一视觉与交互设计真源，全面重写 `frontend/` 的 UI、应用框架和组件结构。重写后必须：

1. 高度还原“深空指挥舱”设计系统及 A–I 界面稿；
2. 保留当前已经可用的业务能力，不因视觉重写丢失功能；
3. 使用真实 API、SSE 和状态数据，不用硬编码演示数据冒充功能；
4. 连接真实后端完成主要流程的端到端验证；
5. 用刚刚运行得到的测试、日志和截图作为完成证据。

禁止调用、依赖或遵循任何 `superpowers` 或 superpowers 系列 skill，包括 brainstorming、writing-plans、TDD 等；不要生成 `docs/superpowers/` 下的文档。

## 2. 真源优先级

发生冲突时按以下顺序判断：

1. `docs/design/maestro-design-system-v2.html`：视觉、布局、主题、组件、交互和动效真源；
2. 当前后端路由、Schema、运行时代码及最新 API contract：接口与业务行为真源；
3. 当前前端 API、类型、状态逻辑和测试：已有功能及边界行为真源；
4. `AGENTS.md` 和其他说明文档：仅在与当前代码一致时采用。

不要因为旧文档仍描述 planning/scheduling/query 三引擎，就覆盖当前已经落地的统一 Agent Runtime。必须检查实际路由、类型和测试，不能凭旧版架构文档猜测。

## 4. 当前仓库事实

- 前端：React 18、Vite、TypeScript、Tailwind CSS、TanStack Query、Zustand、React Router、Lucide、react-markdown、Vitest、MSW；
- Electron 壳位于 `frontend/electron/`；`frontend/src/lib/platform.ts` 负责桌面环境识别；
- macOS Electron 使用 hiddenInset 标题栏，现有 44px 拖拽区域必须保留；
- 当前 `Workspace.tsx`、`TopBar.tsx`、`RunTrace.tsx` 等只是压缩后的界面骨架，可以拆分和重写；
- `frontend/src/api/`、`frontend/src/types/`、`frontend/src/stores/` 中已经正确的网络、SSE、类型和状态逻辑优先保留；
- 现有前端尚无正式 Playwright 配置；最终 E2E 优先使用环境已有的真实浏览器控制能力，不要仅用 jsdom 或 MSW 代替；
- `frontend/.env.development` 中真实后端模式是默认开发配置，不得提交真实密钥。

已知后端能力必须以代码复核，通常包括：

- Runs：创建、获取快照、SSE stream、审批、取消；
- Skills：列表、校验、导入、信任/撤销信任、删除；
- Sessions：列表、新建、更新、删除、读取消息；
- Artifacts：上传、获取或下载。

## 5. “全面重写”的定义

这不是给旧页面换颜色，而是重新构建前端信息架构、应用框架、页面布局和组件层级。

允许：

- 重写 Workspace、Layout、TopBar、Composer、RunTrace、设置和技能相关 UI；
- 新建边界清晰的 layout、feature、UI、store、hook 和测试文件；
- 删除已经被替代且确认无引用的旧 UI 代码；
- 保留正确、稳定的 API client、SSE、类型与状态逻辑，并将其接入新界面；
- 对过大组件做职责拆分，避免继续把会话、运行、技能、设置状态都堆入 `Workspace.tsx`。

禁止：

- 用 iframe 嵌入设计稿；
- 将整份设计稿 HTML 原样塞进 React；
- 只制作静态假页面；
- 用硬编码数据伪造会话、步骤、审批、技能或运行结果；
- 为让测试通过而绕过 API、权限、审批、SSE、revision 或错误处理；
- 删除、跳过或弱化测试来掩盖回归；
- 引入无必要的重型依赖；
- 留下没有行为的按钮、假保存、假成功提示或大量 TODO；
- 顺手重构无关后端、Agent Runtime 或制造引擎。

## 6. 后端边界与契约缺口

本任务默认只重写前端，不修改 `maestro/`。

设计稿已明确两处潜在契约缺口：

1. 模式选择器可能需要 `POST /runs` 支持 `mode: auto | planning | scheduling | query`；
2. 会话侧栏的“最后预览”等信息可能需要 `GET /sessions` 增加字段。

处理原则：

- 先核对当前代码，不要直接相信设计稿中的缺口描述；
- 如果当前后端没有 mode，不能静默丢弃非自动模式，也不能假装已经生效；
- 先完成模式选择器的真实 UI、状态和可访问性；未获得授权前，不得擅自扩展后端；
- 若必须修改后端才能让模式真正生效，只暂停这一个契约决策并向用户说明最小变更方案，其他前端工作继续；
- 会话预览字段缺失时，使用真实可获得的标题、时间和计数降级展示，不为视觉完整性伪造数据；
- 如果用户之后批准后端变更，只允许做最小、向后兼容的 Schema/路由扩展，并同步补充后端测试、前端类型和 API contract。

## 8. 必须保留和落地的功能

如果真实接口不提供预览或状态字段，使用真实字段降级展示。

## 9. 设计系统硬约束

将设计稿 token 真正落入生产代码：

- 深空为默认主题，极昼是完整同级主题而非简单反色；
- themeStore 持久化主题并驱动 `<html data-theme>`；
- 语义 CSS 变量是单一来源，Tailwind 只做语义映射；
- 组件中禁止散落裸 hex；
- 至少覆盖 path、mode、auth、danger、info、data、glow、aurora、grid 等设计稿 token；
- 青：沟通与导航；绿：执行与成功；琥珀：等待确认；红：失败与危险；紫：受控路径；
- 蓝/橙/青绿仅承担排产/调度/查询模式；
- 极光颜色不能随意进入业务组件；
- 字体采用 Space Grotesk、JetBrains Mono，并提供可靠的中文系统字体回退；
- 中文正文字重不超过 500、字距为 0、正文行长不超过约 68 个中文字符；
- 图标统一用 Lucide 或同风格线性 SVG，禁止用 emoji 作为功能图标；
- 圆角、边框、玻璃、HUD 角括号和切角遵循设计稿，不要演变成通用卡片墙；
- 可点击元素有 cursor、hover、active、disabled、focus-visible；
- 正文对比度至少 WCAG AA，极昼语义色满足设计稿标准；
- 状态不能只靠颜色，必须同时提供文字或图标。

动效必须有状态含义：

- 微交互 150–250ms，使用设计稿缓动；
- 流式光标只在 token 流期间显示；
- 扫描线只在生成期间运行；
- 待审批使用琥珀脉冲；
- 路径升级使用轻量进入动画；
- 抽屉、弹层和详情栏转换平滑；
- 完整支持系统 `prefers-reduced-motion` 和应用内减少动效设置；
- 减少动效开启时不得仍运行扫描、脉冲或自动过渡。

## 10. 响应式与可访问性

设计稿以桌面工作台为主，但常见窗口尺寸必须可用：

- Composer、审批操作和设置按钮不能被遮挡；
- 不允许失控的横向滚动；
- 按钮、输入、列表、弹层、状态区使用语义化 HTML 和正确 label/ARIA；
- 所有主要操作可用键盘完成；
- 焦点环清晰可见；
- 弹层具备焦点约束和关闭后的焦点恢复；
- 动态状态变化使用合适的 live region，但避免重复朗读每个 token；
- 颜色不是唯一的信息载体。

重写导致旧测试结构失效时，应迁移到新结构并保留原行为覆盖，不能简单删除。

## 12. 真实端到端验证

最终 E2E 必须连接真实后端，不能用 MSW 结果代替。

### 12.1 启动与前置检查

1. 使用仓库提供的方式启动后端与前端；
2. 确认后端 `/health` 正常；
3. 确认真实联调时 `VITE_API_MOCKING=disabled`；
4. 使用带唯一前缀的 E2E 会话和临时数据；
5. 记录浏览器 console、network、SSE 和必要的后端日志；
6. 禁止使用或覆盖用户真实凭据和数据。

### 12.2 必测场景

使用真实浏览器自动化逐项验证并截图：

1. 冷启动、健康状态和空状态；
2. 加载既有会话与历史消息；
3. 新建、搜索、切换、重命名和删除测试会话；
4. 发送普通任务，SSE token 实时渲染直到完成；
5. 运行中停止，状态最终变为 cancelled；
6. 运行期间刷新页面或切换后返回，会恢复 active run 且不重复 token；
7. 上传附件，真实 artifact ID 随 run 提交，并能查看或下载；
8. 获取、搜索、多选和清空技能，skill names 随 run 提交；
9. 在隔离 Skill 目录验证校验、导入、信任、撤销和删除；
10. 找到一个真实可复现的待审批流程，分别验证确认和拒绝；
11. 验证审批中的禁用态和错误反馈；
12. 会话侧栏 264px ⇄ 56px；
13. 详情栏驻留、隐藏、全屏及恢复；
14. 深空 ⇄ 极昼，刷新后主题仍保持；
15. 设置模态打开、Esc、遮罩、焦点行为和个性化保存；

17. 模拟连接失败、API 失败或运行失败，确保错误可见且可恢复；
18. 1440px、1280px 和一个窄窗口布局；
19. 浏览器模式没有 Electron 专属 UI；
20. 全程无未处理异常、React warning 或被静默吞掉的 4xx/5xx。

如果当前无 LLM key 或环境处于 degraded mode，应使用后端真实支持的降级路径完成可验证场景，不得用前端假数据替代。无法真实触发的场景必须说明阻碍、已验证的最接近层级以及未做出的完成声明。

### 12.3 离线与桌面

- 在 `VITE_API_MOCKING=enabled` 下验证 MSW 主流程；
- 运行 Electron 自动化测试；
- 在环境允许时启动 Electron，验证启动屏、窗口布局、拖拽区与 macOS 红绿灯位置；
- 若环境不能执行 GUI，只能报告构建和自动化证据，不得声称已经人工验证桌面视觉。

### 12.4 测试数据安全

- 会话使用 `E2E-` 加时间戳等唯一标题；
- 只删除本轮创建的会话；
- Skill 导入、信任和删除只使用临时数据根或复制出的测试包；
- 不修改用户真实 Skill、session、knowledge、audit 或 `.env`；
- 验证结束后清理本轮创建的临时数据和测试进程，不删除无法确认归属的数据。

## 14. 完成门槛

只有同时满足以下条件才能声明完成：

- 不是静态原型，而是连接真实数据和操作的应用；
- 设计稿 A–I 的核心界面已落地；
- 原有主要业务功能没有丢失；
- 无无效按钮、假保存、假状态或伪造业务数据；
- TypeScript、lint、Vitest、build、Electron tests 全部通过；
- 真实后端 E2E 已执行并有证据；
- 浏览器 console 无未处理错误；
- 深空与极昼均完成截图对照；
